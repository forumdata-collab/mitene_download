1架構原理

Mitene 網頁版逐頁 API 拉取相簿內容，每項媒體一個下載 URL。Script 並行 4 個下載，已有檔案自動 skip（斷點續傳）。

Mitene 網頁 API→逐頁 pagination→並行下載 (×4)→YYYY-MM/ 分類→(可選) rclone → GDrive

2事前準備

全部免費。需要：雲端 VM（或任何長期開機的電腦）、Python 3.10+。

  • 取得相簿分享 URL

    喺 Mitene app 邀請一位家庭成員使用網頁版，就會得到形如 https://mitene.us/f/abcd123456 嘅 URL。

  • （轉存版）設定 rclone + GDrive

    rclone config → 揀 drive → 跟指示授權 → remote 名建議 gdrive。

3安裝
pip install git+https://github.com/forumdata-collab/mitene_download.git

或者 clone 落 VM 直接用：

git clone https://github.com/forumdata-collab/mitene_download.git
cd mitene_download && pip install -e .
4基本用法（本地版）
mitene_download https://mitene.us/f/abcd123456 --destination-directory out

密碼保護相簿會提示輸入；自動建立 out/YYYY-MM/ 子目錄，檔名 = YYYYMMDD-6字CDN識別碼。重跑同一指令只會補漏（已有檔案 skip）。

輸出結構：out/2024-05/20240501-a1b2c3.jpg · 留言存成同名 .md。實例：
out/
├── 2024-05/
│ ├── 20240501-a1b2c3.jpg
│ ├── 20240501-a1b2c3.md ← 該相嘅留言
│ └── 20240530-d4e5f6.mp4
├── 2024-06/
│ └── ...
├── download.log ← 每次執行統計
└── errors.log ← 失敗檔案逐行記錄
5Fork 新功能速查
參數預設作用
--cooldown N0.3 秒下載之間 jitter sleep；0 關閉；遇 429/5xx 自動指數退避重試（最多 4 次）
--no-organize開關閉年月子目錄，回復 upstream 平面輸出
--gdrive-upload REMOTE:FOLDER關下載完成後 rclone move 到 GDrive（整批，需本地容量）
--stream-daemon CMD關長駐上傳程序（推薦）：下載一個即傳一個，VM 唔保留檔案；附 stream_gdrive.py --daemon helper，GDrive 結構自動 mitene-backup/YYYY/MM/
--stream-command CMD關每檔下載完執行指定命令，{file} 替換成檔案路徑（慢，每檔 spawn 新 process）
--months YYYY-MM,...—只下載指定月份（如 --months 2024-05,2024-06）
--since YYYY-MM—只下載呢個月之後嘅所有月份
--dry-run關執行前評估：總檔數 / 已下載 vs 待下載 / 總大小 / 預計耗時，唔下載任何檔案
--bandwidth-mbps N100dry-run 估算用嘅頻寬（影響預計耗時）
--concurrency N4並行下載數；大量影片可調低（--concurrency 2）
--password-file FILE—由檔案讀密碼，避免 `ps` 見到（較安全）
--nocomments關唔下載留言 .md 檔

每次執行後會喺 out/download.log 追加一行：

[2026-08-15T08:11:01] url=https://mitene.us/f/abc added=3 skipped=10 failed=1 -> out/
6轉存 GDrive（流式，推薦）

長駐 daemon 一次 spawn，下載一個即傳一個，VM 唔保留檔案（適用大相簿 + 細 VM 磁碟）：

mitene_download https://mitene.us/f/abcd123456 --password-file ~/album.pass \ --stream-daemon "python3 stream_gdrive.py --daemon"

GDrive 自動建立 mitene-backup/YYYY/MM/ 結構（folder id 快取喺 .stream_folder_id，已 gitignore）。原圖下載（download endpoint），檔名 YYYYMMDD-6字碼.jpg。

舊方法（整批 rclone）：--gdrive-upload gdrive:mitene-backup 落完先一次過搬，需要 VM 有全相簿容量；--stream-command 每檔 spawn 新 process（慢），三選一。
流式版注意：上傳失敗嗰個檔會留喺本地，重跑自動補傳；唔會刪家家相簿任何嘢（純讀取）。
7自動排程

每日凌晨自動補漏（已有檔案 skip，所以重跑好安全）：

crontab -e
# 每日 03:00 同步一次
0 3 * * * cd ~/mitene_download && mitene_download https://mitene.us/f/abcd123456 --destination-directory out >> /tmp/mitene_cron.log 2>&1
點樣確認有冇新嘢？睇 out/download.log 最尾一行 —— added=N 大過 0 即有新檔。
8常見坑
問題解
第一次用 organise 後全部重新下載舊平面檔名同新 YYYY-MM/ 路徑唔同，第一次會重拉。已加 migrate：開頭自動搬舊檔入對應月份，搬完就唔會重下載。
下載中斷留低 .tmp下次執行開頭自動清理，唔使手動刪。
429 / 下載失敗自動指數退避重試 4 次（1s→2s→4s→8s 加 jitter）；仲係失敗會記入 log 同 stderr。
唔想佢 sleep 咁密--cooldown 0.1 加速；--cooldown 0 完全關閉（有被鎖風險，唔建議）。
URL 過期（expiringUrl）每個媒體嘅下載 URL 即場由頁面 API 攞，唔會過期；整條 album URL 先係長期有效嗰條。
⚠️ stream-daemon 模式檔案「下載成功但 GDrive 冇檔案」（2026-08-15 實測，2837 檔全 lost）根因：--stream-daemon 舊版喺寫 path 去 daemon 之後立即 unlink 本地檔，但 daemon 係由磁碟讀檔上傳——unlink 先過 upload 就 race，stream_gdrive.py 第一行 os.path.exists() check 失敗 → 靜默 skip，檔永久 lost（download.log 仲報 added=2837 skipped=0，誤導）。已修：downloader 唔再 unlink，由 daemon upload 成功先刪。驗證：跑完對比 GDrive 實際檔數（見下方 Q&A「點確認真係上晒」）。
daemon 一直唔退（wait timeout 3600s）正常現象：downloader 寫完 2837 行 path 就完成，但 daemon 係一個一個排隊 upload，大 album 要 upload 完先退。download.log 寫咗 summary 唔代表 upload 完。檢查：ps aux | grep stream_gdrive 有 process = 仲 upload 緊；find out -type f 數目遞減 = 正常。等 daemon 自然退出，或者直接再跑一次（已有檔 skip，只補漏）。
9Q&A 常見問題
問題答
可以反方向同步嗎（GDrive → 家家相簿）？唔得。本工具只行公開嘅 GET /media_files/{uuid}/download 端點；上載係寫入操作，要逆向私有上載 API + 重寫成上傳器，而且違反 FamilyAlbum 使用條款風險。方向固定：家家 = 源，GDrive = 備份。
VM 需要幾大容量？可以邊下邊傳唔使存晒嗎？預設 --gdrive-upload 係「全部落完 → rclone move」— VM 需要成個相簿容量。流式方案（零代碼）：rclone mount gdrive:mitene-backup ~/mnt --daemon 然後 --destination-directory ~/mnt/out 直接寫入掛載點，VM 磁碟峰值 = 並行 4 × 單檔大小。
成個相簿要下載幾耐？公式 ≈ 檔案數 × (平均大小 ÷ 頻寬 + 0.3s cooldown)。例：10,000 張 × 3MB = 30GB，100Mbps VM ≈ 1.5 小時（下載 ~40 分鐘 + cooldown 開銷）。影片（1GB+）另計。頻寬係樽頸，唔係 CPU。
斷線可以繼續嗎？可以。已有檔案自動 skip，重跑只補漏。⚠️ 但 --gdrive-upload（move）係「傳完刪本地」——傳到一半斷咗，本地已刪 → 會重新下載。想斷線安全用 mount 或者 rclone copy（唔刪本地）。
無 VM 用戶點算？（a）屋企舊電腦常開行 cron — $0，最簡單。（b）Android 舊電話用 Termux 裝 Python + rclone — $0 迷你 VM（iOS 做唔到）。兩者都係「機喺你手」，私密相片唔離開你控制。
可以整網頁版，即下即上唔經 VM 嗎？做唔到。瀏覽器直接由 mitene 下載 → GDrive 需要跨兩個網域：mitene 唔開放 CORS（私有相簿），GDrive 直寫要 OAuth client，大影片喺瀏覽器記憶體傳輸唔穩定。任何純前端方案都要一個後台代理——個代理就係 VM，繞唔到。
用 Google 免費服務（Apps Script / Cloud Functions）做中轉？兩個都唔啱：Apps Script 單次執行 6 分鐘上限 + 單個 response 20MB——影片全部超標；Cloud Functions 免費 tier 要綁信用卡先開到，而且本質都係中轉伺服器。微縮版（只拉縮圖清單）可以，全相簿連影片過唔到紅線。
可以只同步指定年月份嗎？可以。--months 2024-05,2024-06 指定月份；--since 2024-01 只拉 2024 年 1 月之後。
點知成個相簿有幾大、要跑幾耐？先跑 --dry-run：掃描全部頁面，統計總檔數（相片/影片分佈）、總大小（未知大小以 3MB 估）、預計耗時（--bandwidth-mbps 改頻寬）。唔會下載任何檔案，確認滿意先正式跑。
下載有失敗點 debug？每次執行結束，失敗檔逐個寫入 out/errors.log（時間戳標題 + 每行 名稱: 錯誤訊息），同時 download.log 有 added/skipped/failed 總數。重跑只會補漏失敗嗰啲。
點確認 stream 模式真係全部上晒 GDrive？download.log 嘅 added 只係「下載咗幾多」，唔等於「上傳咗幾多」。跑完之後：
① find out -type f 應該得 download.log（有殘留 = 未 upload 完或失敗）
② 用 Google Drive API 數 mitene-backup 下所有檔案總數，同 album 總數（--dry-run 報嘅數）對比
③ 差幾十個以內 = 正常（重跑自動補）；差成千個 = 中咗上面 stream race bug，即刻升級 fork。
debug 提示：以下係 2026-08-15 實測結論——CORS、Apps Script 6 分鐘/20MB 紅線、rclone move 斷線重拉，呢三點係後人最易撞返嘅牆。

11家家相簿（FamilyAlbum）是什麼

家家相簿由日本 mixi 株式會社開發，係家族專屬嘅相片與影片分享 App，繁體中文版 2020 年 1 月喺台灣正式推出。截至 2019 年底全球用戶突破 600 萬，喺日本每三位媽媽就有一位使用。核心理念係「令育兒更加開心」——提供一個父母安心、安全噉同家族成員分享孩子成長紀錄嘅私密空間，避免喺公開社群曝光孩子相片嘅風險。

功能說明
免費無限上傳相片與影片免費、無容量限制上傳，唔怕手機空間唔夠或舊檔被刪
私密分享只限受邀家族成員觀看，可設「全體家族公開」或「僅限管理員（父母）」
自動按月整理按拍攝日期與孩子月齡自動分類，滑動即回顧成長軌跡
家族留言互動每張相片影片可留言，祖父母都輕鬆參與
1 秒短片集上傳超過 20 部影片自動擷取每部 1 秒，製成季節/年度回顧短片
實體商品訂製實體相簿、DVD，每月免費沖印 11 張相片
電腦上傳瀏覽器上傳數位相機或舊相（白金會員功能）

進階：去重複、按年檢測、半年度續存（v0.9.4）

v0.9.2 加入四個配套工具；v0.9.4 統一 GDrive 層 + 去重升級做 md5 三重驗證。

  • 去重機制（stream_gdrive.py）：上傳前對比 GDrive folder 嘅 (name, size, md5)——三名全符先 skip，重跑零重複；同名同 size 但 md5 唔同 = GDrive 上係舊/壞檔 → 以本地（由 album 新拉）為準重新上傳；另加 120 秒 socket timeout，單個 hung upload 唔會再卡死成條 pipeline
  • 共享 GDrive 層（gdrive_utils.py，v0.9.4 新增）：OAuth service、folder 查詢/建立、folder listing（免費附 md5Checksum）、遞歸計數、local_md5() 全部收歸一處，唔再喺 6 個 script 重複抄寫
  • 按年檢測（check_years.py）：逐年份 dry-run + GDrive 實數 → .album_counts.json；Web UI 嘅 Check 按鈕同 cron runner 共用同一份資料，唔會各自掃描
  • 半年度續存（sync_year.py + cron，v0.9.3 逐月制）：每日一個半年度（2021 H1 → H2 → 2022 H1…）；每個月順序做：下載 → 上傳 → 覆查本地清零 → 刪 VM 檔 先至開始下個月 — 上傳失敗嘅檔會留喺 VM（唔會誤刪），state 記住完成咗邊啲月，斷咗聽日直接續嗰個月，唔會重下載；flock 防 check 同 sync 互撞；已完成年份由 cache 跳過
  • 一次性清理（dedupe_cleanup.py）：按 (folder, name) 分組，md5 相同先刪、每組留一 — 2026-08 實測清走 ~9,500 個舊重複檔，釋放 ~37GB 配額
  • 缺口診斷 + 定向補檔（diag_full.py / backfill_gap.py）：diag_full 逐月比對 album vs GDrive 檔名，搵出確切缺檔；backfill_gap 全頁掃描 + 按 uuid 補返缺檔（v0.9.4 修正早停 bug，月頭 boundary 檔唔會再漏）
⚠️ 改檔名格式之前諗清楚：舊格式同新格式嘅檔名唔同名，name+size 去重會判為「唔重複」→ 產生跨版本重複上傳（2025/2026 嘅 ~8,500 個重複就係咁嚟）。UUID 長度改動建議只喺全新 GDrive 結構上做。

白金會員（付費方案）

免費版已涵蓋大部分核心功能，升級白金會員可享：影片長度 2→10 分鐘、Full HD（1920×1080，Pro 方案）、電腦批次上傳、個別相簿與成長紀錄、詳細公開範圍（細分媽媽/爸爸親屬權限）、實體商品免運費、Chromecast 投放電視。

關鍵規則：相簿中任一成員註冊白金會員，全體家族成員一齊享用進階功能，首次註冊享 1 個月免費試用。

適合誰使用？

  • 想記錄孩子成長、但唔想喺 Facebook / Instagram 等公開平台分享嘅父母
  • 想祖父母、外祖父母隨時見到孩子近況嘅家庭
  • 相片影片量大、手機容量成日唔夠嘅使用者
  • 想將數碼回憶製作成實體相簿或 DVD 保存嘅家庭
同本教學嘅關係：免費無限上傳係賣點，但唔保證永久保存——本地備份先係最穩陣。本頁就係教你將成個相簿「搬返屋企」。
